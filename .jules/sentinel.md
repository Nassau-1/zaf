## 2026-06-01 - Command Injection in Git Clone via execSync
**Vulnerability:** Arbitrary command injection via unsanitized user inputs (`remoteUrl`) passed to `execSync` string interpolations for commands like `git clone`, `git config`, `git init`, and `git remote`.
**Learning:** Using string interpolation with `execSync` executes the entire string via a subshell by default, allowing attackers to terminate the intended command and inject their own using shell metacharacters (e.g., `;`, `&`, `|`).
**Prevention:** Use `execFileSync('git', ['clone', remoteUrl, ...])` instead. This bypasses the shell completely and directly invokes the executable with a safe array of arguments, preventing any injected shell operators from being evaluated.

## 2026-06-24 - Enhance URI decoding and boundary validation
**Learning:** Using `startsWith` for boundary validation without a path separator can allow prefix matching on longer paths. Also, not decoding URLs properly can incorrectly pass certain logic checks.
**Prevention:** Use `decodeURIComponent` in a try-catch block and always append `path.sep` to directory paths when using `startsWith`.

## 2026-06-25 - Prevent Path Traversal in Node.js HTTP Server Repository Resolution
**Vulnerability:** The HTTP server resolved repository paths using `path.resolve(REPOS_ROOT, repoSlug)` and `path.join(REPOS_ROOT, repoSlug)`. Since `repoSlug` is user-controlled via API parameters, this allowed path traversal. If an attacker supplied a sibling directory (e.g. `../repos-secrets`) or URL-encoded sequences (e.g. `%2e%2e%2f%2e%2e%2fetc%2fpasswd`), they could escape the intended `REPOS_ROOT` directory because there was no strict containment check or proper decoding before resolution. Furthermore, throwing synchronous errors in the path resolution logic can cause Denial of Service (DoS) by crashing the server because it lacks centralized error handling.
**Learning:** In Node.js, `path.resolve` and `path.join` implicitely normalize paths, but they do not guarantee containment within a root directory if traversal sequences like `..` are used. A simple `.startsWith(ROOT)` check is vulnerable to sibling directory traversal. The input must also be URL-decoded before validation to catch encoded bypass payloads. Finally, to prevent DoS, decoding or resolution errors should fail safely rather than throwing.
**Prevention:** Always URL-decode user input (`decodeURIComponent`) before path resolution. Always verify containment by checking that the resolved path is exactly equal to the root OR strictly starts with the root appended with a path separator (`resolved === ROOT || resolved.startsWith(ROOT + path.sep)`). Return a known invalid path (e.g., `path.join(ROOT, '__INVALID_PATH__')`) on validation failure to ensure downstream `fs` operations cleanly fail with `ENOENT` instead of crashing the server with synchronous throws.
