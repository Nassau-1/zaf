## 2026-06-01 - Command Injection in Git Clone via execSync
**Vulnerability:** Arbitrary command injection via unsanitized user inputs (`remoteUrl`) passed to `execSync` string interpolations for commands like `git clone`, `git config`, `git init`, and `git remote`.
**Learning:** Using string interpolation with `execSync` executes the entire string via a subshell by default, allowing attackers to terminate the intended command and inject their own using shell metacharacters (e.g., `;`, `&`, `|`).
**Prevention:** Use `execFileSync('git', ['clone', remoteUrl, ...])` instead. This bypasses the shell completely and directly invokes the executable with a safe array of arguments, preventing any injected shell operators from being evaluated.

## 2024-06-05 - Path Traversal via Substring and Null Byte Bypasses
**Vulnerability:** Path traversal and local file inclusion via flawed substring bound checks (`filePath.startsWith(STATIC_DIR)`) and lack of URL decoding/null byte validation in static file serving logic.
**Learning:** Checking bounds with `startsWith` allows bypassing the check if an attacker requests a sibling directory that shares the same prefix (e.g. bypassing `/app/dashboard` via `/app/dashboard-secrets`). Additionally, failing to `decodeURIComponent` hides payloads like `%2e%2e/` from early path normalization, and omitting null byte checks allows poison null byte attacks (`%00`) to truncate file extensions. Raw HTTP requests via `net.Socket` must be used to test since `http.get` normalizes paths locally.
**Prevention:** Always `decodeURIComponent`, strictly check and reject `\0` null bytes, and use `path.resolve()` on paths. For boundary checking, append the platform-specific directory separator (`STATIC_DIR + path.sep`) before calling `startsWith()`, or use exact path equality checks for root elements.
