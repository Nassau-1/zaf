## 2026-06-01 - Command Injection in Git Clone via execSync
**Vulnerability:** Arbitrary command injection via unsanitized user inputs (`remoteUrl`) passed to `execSync` string interpolations for commands like `git clone`, `git config`, `git init`, and `git remote`.
**Learning:** Using string interpolation with `execSync` executes the entire string via a subshell by default, allowing attackers to terminate the intended command and inject their own using shell metacharacters (e.g., `;`, `&`, `|`).
**Prevention:** Use `execFileSync('git', ['clone', remoteUrl, ...])` instead. This bypasses the shell completely and directly invokes the executable with a safe array of arguments, preventing any injected shell operators from being evaluated.
## 2026-06-03 - Path Traversal Bypass in Static File Server
**Vulnerability:** A directory traversal vulnerability allowed attackers to read arbitrary files outside the `STATIC_DIR` boundary. The check `!filePath.startsWith(STATIC_DIR)` could be bypassed if the requested path contained encoded traversal sequences (e.g. `%2e%2e`) that weren't decoded, or by accessing paths that shared the same prefix as `STATIC_DIR` (e.g. `/app/dashboard-backup` instead of `/app/dashboard`).
**Learning:** Using `String.prototype.startsWith` on file paths is susceptible to prefix-matching bypasses. Furthermore, failing to decode URL-encoded parts of a path (`decodeURIComponent`) prevents standard path normalization from resolving traversal segments correctly.
**Prevention:** Always decode user-supplied paths (`decodeURIComponent`), normalize them fully using `path.resolve`, and append the directory separator (`path.sep`) when using `startsWith` for boundary enforcement (e.g. `!filePath.startsWith(staticDirResolved + path.sep) && filePath !== staticDirResolved`).
