## 2024-05-15 - [CRITICAL] Fix path traversal in repo endpoint resolution
**Vulnerability:** User inputs specifying repository names (e.g. `repoSlug`, `repoName`) were being joined/resolved against `REPOS_ROOT` using `path.resolve` or `path.join` without verifying that the resolved path actually stayed within `REPOS_ROOT`. This allows a malicious user to craft an HTTP request with `../` characters and achieve path traversal (Local File Read/Write/RCE via arbitrary file overwrites or accessing secrets like `.secrets.json`).
**Learning:** Node.js' `path.resolve` naturally climbs up directories when given `..`. Even `path.join` does this. The API relied on these methods directly without bounds checking the resulting absolute paths. Unhandled errors crashing `http.createServer` handlers create DoS vulnerabilities, so the validation must return gracefully (e.g. returning a specific error block or sending a `400` status).
**Prevention:** Always use a bounds-checking helper function (e.g., `resolveSafeRepoDir`) that verifies the resulting path starts with the base directory and returns `null` if the bounds check fails, instead of blindly resolving paths. Make sure it's applied correctly across all routes and background tasks that process untrusted file paths.
