## 2025-05-16 - Prevent Path Traversal in Server Route Handling
**Vulnerability:** The HTTP server paths like `/api/repo/context`, `/api/ticket/status`, and others were concatenating or resolving `REPOS_ROOT` directly with unsanitized user inputs (e.g., `req.query.repo` or `req.body.repo`). This allowed for path traversal (e.g., accessing sibling or higher-level directories via `../../`).
**Learning:** Node.js path resolvers (`path.resolve`, `path.join`) are vulnerable to directory traversal if inputs aren't checked against an absolute root base path using secure techniques. Simple substring checks without a directory separator allow sibling-level directory access.
**Prevention:** Implement a standard `resolveRepoRoot` function that decodes URI components and verifies the resolved path starts exactly with `REPOS_ROOT + path.sep` or matches exactly `REPOS_ROOT`, returning an invalid path token (`__INVALID_PATH__`) upon failure to ensure `fs` operations safely `ENOENT`.
